# Publish the portfolio operating system

Turn the accepted analysis into governance that another operator can follow without reinterpreting the evidence.

- `workflow_portfolio_operating_system` groups actual recommendations by posture, explains sequencing and decision rights, and includes `create_next` only where supported. Empty categories may be stated as such.
- `portfolio_operating_summary.json` contains `workflow_name`, `focus_workflows`, `analyzed_workflows`, `lifecycle_recommendations`, `governance_posture_counts`, `change_candidate_ids`, `priority_workflows`, `authoritative_artifacts`, `next_action`, `publication_boundary`, and `ready_for_publication`. The boundary is `operating_system_publication_only`.
- `portfolio_next_actions` identifies owners or roles, prerequisites, evidence of completion, review triggers, and safe stopping points.

Accept only when lifecycle facts and candidate IDs match analysis. Rework packaging drift; replan if recommendations must change. This phase publishes decisions but does not enact them.
