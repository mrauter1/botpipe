# Optimizer v2 acceptance coverage

This matrix maps the acceptance cases in `docs/requirements/optimizer-v2.md` to tests in the current repository. It is an inventory of test intent, not a replacement for a passing CI run.

Status meanings:

- **Covered**: the required behavior is exercised directly by one or more named tests.
- **Partial**: important parts are exercised, but at least one clause in the acceptance row lacks a direct assertion.
- **Gap**: no direct test was found for the material behavior.

## Verification scope

All T01–T20 rows have direct regression coverage. The full suite, Linux CI, Windows containment/contract checks, and wheel/sdist builds are required to pass on the final change before merge. These tests validate the specified mechanisms and failure cases; they do not claim that a proposed optimization improves an unseen workload. Improvement remains `not_evaluated` unless a frozen paired evaluation supplies valid comparable results.
