# Optimizer v2 acceptance coverage

This matrix maps the acceptance cases in `docs/requirements/optimizer-v2.md` to tests in the current repository. It is an inventory of test intent, not a replacement for a passing CI run.

Status meanings:

- **Covered**: the required behavior is exercised directly by one or more named tests.
- **Partial**: important parts are exercised, but at least one clause in the acceptance row lacks a direct assertion.
- **Gap**: no direct test was found for the material behavior.

## Prioritized untested clauses

1. **Publication and resume drift (T04, T15):** add an integration test that pauses after baseline capture, corrupts the frozen baseline/checkpoint, resumes, and proves the prior accepted receipt is replaced by an incomplete receipt. Add a second hook that mutates the candidate after validation and before commit.
2. **Exact invalid-candidate publication path (T01):** run the named `ralph_loop` scenario through validation publication, including the editable-installed variant, and assert both validation failure and absence of an accepted receipt.
3. **Raw symlink escape (T05):** create a run-relative raw reference whose path traverses a symlink component and assert `invalid_path`, no copied bytes, and no citable raw evidence.
4. **Complete forged-manifest matrix (T03):** parameterize candidate root, mode, per-file digest/size/executable metadata, changed/added lists, total counts, and content IDs; assert recomputation or rejection at the public validation and receipt boundary.
5. **Selection semantics (T11):** add one fixture combining failure-only runs, `route_tags=[]`, admitted denominator assertions, Python/model structural names, and report checks that no probabilities are invented.
6. **Git invariance (T06):** capture equivalent traces with absent, empty, and disabled Git records and compare normalized observations byte-for-byte except for the declared optional-gap field.
7. **Historical checkpoint compatibility (T20):** enumerate maintained checkpoint/artifact schema versions and test readable migration versus explicit unsafe-resume rejection. The current tests cover legacy evidence fields and parameter aliases, but not the full supported checkpoint matrix.
8. **Report wording (T12):** render a mixed-provider, partial-usage recommendation and assert the report describes resource gaps without cost/efficiency claims.
9. **Residual lineage/process clauses (T08, T16):** add a normal multi-visit lane with no rejection/return, a special-file execution tree, and a noisy built-in CLI provider with a descendant so cleanup and live stream caps are tested together.

The optimizer v2 release gate depends on T01–T16 and T19–T20. The highest-priority remaining gaps are therefore the T04/T15 resume-publication drift case and the T01 end-to-end invalid-candidate receipt case. Paired validation T17–T18 has direct unit coverage and a refinement integration path, including symmetric frozen evaluator requests.
